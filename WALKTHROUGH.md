# How the revised generator runs

Read this alongside a generated example's `lesson-plan.json` and `trace.jsonl`. These are real authored data and recorded execution, not a model's private reasoning.

1. **Command and source.** `agent.py` reads the three-field input and supplied model ID. `playground/orchestrator.py` owns the shared runtime, call and completion-token budget. `playground/source/pipeline.py` downloads/parses the paper and `playground/retrieval/retrieve.py` chooses evidence chunks. Evidence IDs are generated from the source, not invented by the model.
2. **Model's responsibility.** `playground/model/lesson_plan.py::plan_messages` describes the restricted expression language and asks for scientific explanations, actual inputs, expression steps, visuals and two presets. The model chooses the scientific mathematics. A schema-valid response can still contain incorrect science.
3. **Compiler's responsibility.** `compile_plan` assigns `var-`, `compute-`, `eq-`, `control-` and `explore-` IDs. It parses each expression's identifiers and maps them to declared scientific variables. It derives dependencies, control types and downstream effects. The teaching equation is the executed expression; it is classified as derived rather than claimed to be a verbatim source equation. The compiler does not fix an incorrect scientific formula.
4. **Execution and correction.** `playground/ir/validate.py` checks declarations, provenance, focus coverage, calculations and representative input states. `playground/computation/parser.py` accepts only the restricted AST; it never evaluates arbitrary Python. `operations.py` defines mathematical primitives and `evaluator.py` executes them. `validate.py` checks defaults, scalar boundaries, independently chosen array probes and exploration setups. `model/generation.py` sends concrete failures back for at most three authoring attempts, all using the original run budget.
5. **Computed observations and scientific review.** `model/observations.py` calculates each exploration's numeric observation from its actual preset and default values; model-predicted numbers are not presented as observations. Qualitative explanations remain model-authored and reviewed. `model/scientific_review.py` gives the same supplied model the retrieved evidence, executable expressions, control declarations, learner claims and actual computed preset values. The response must include explicit checks and actionable issues for failed checks. An unsupported verdict triggers correction and fresh review. The model can still miss errors, so these findings are evidence of an attempted check, not proof of scientific truth.
6. **Page and browser.** `render/renderer.py` embeds lesson data, CSS and `runtime/canonical.js` in one HTML file. Python and JavaScript implement the same restricted operations. The browser checker opens the page offline, edits the real controls, checks computed values and visuals against Python, applies both presets, clicks Reset and checks responsive widths. It does not count an input event alone as evidence that a control works. `render/pipeline.py` promotes `index.html` only after the artifact and browser gates pass.

For attention, the plan's `matmul(K,q)` calculates one score per key; `softmax` turns scores into weights; `matmul(transpose(V),weights)` forms the value-row weighted sum. Read the plan to see whether scaling is a conditional step and which actual inputs are editable. The corresponding trace shows any rejected drafts, their correction feedback, final scientific findings and browser checks.

To explain a failure, start with the trace's `candidate_rejected` or `failure` entries and inspect the corresponding `candidate.plan.json` / `candidate.ir.json`. `IR_INVALID` identifies a schema, reference, control or executable-contract defect. `GROUNDING_UNSUPPORTED` identifies a scientific/evidence rejection. Source retrieval succeeding does not make either of these stages succeed.

The committed verification briefs are test fixtures. Production code contains mathematical primitives and general lesson infrastructure; it does not choose a page or formula by recognizing those paper titles.
