Explain the core computation of scaled dot-product attention for a single query: similarity scores, softmax-normalized weights, and the weighted combination of values, including the effect of the 1/sqrt(d_k) scaling.

  • Compute attention scores as dot products between a query and each key, and apply the 1/sqrt(d_k) scaling.
  • Convert scaled scores to attention weights with softmax, verify they sum to one, and form the weighted output as a convex combination of value vectors.

Build an intuition

A query is compared with each key by a dot product. Larger dot products mean the query is more similar to that key. Dividing by sqrt(d_k) keeps these scores from growing with dimension, so the softmax stays in a well-behaved range. The softmax turns scores into weights that sum to one, and the output is the weighted average of the value vectors.

Follow the mechanism

  1. Dot product of the query with each key, producing one score per key.
  2. Divide each score by sqrt(d_k) when scaling is enabled; otherwise keep raw scores.
  3. Softmax over the scaled scores, producing a probability distribution over the keys.
  4. Weighted sum of the value vectors, using the attention weights as coefficients.

Two ways to explore

Exploration 1

Equal scores with and without scaling

Change: Set Query vector q to [1.0, 1.0]; Set Key matrix K to [[1.0, 0.0], [0.0, 1.0]]; Set Value matrix V to [[1.0, 0.0], [0.0, 1.0]]; Set Apply 1/sqrt(d_k) scaling to True.

Observe: Calculated results for this setup, compared with the starting inputs: Raw attention scores = [1.0, 1.0] (starting value: [1.0, 0.0]); Scaled attention scores = [0.70710678, 0.70710678] (starting value: [0.70710678, 0.0]); Attention weights = [0.5, 0.5] (starting value: [0.66976155, 0.33023845]); Attention output = [0.5, 0.5] (starting value: [0.66976155, 0.33023845]).

Why: Equal scores always produce uniform softmax weights regardless of the common scale factor, because softmax is invariant to adding a constant to all scores. The scaling changes the magnitude of the scores but not their relative differences when they are already equal.

Exploration 2

Dominant score with and without scaling

Change: Set Query vector q to [3.0, 0.0]; Set Key matrix K to [[1.0, 0.0], [0.0, 1.0]]; Set Value matrix V to [[1.0, 0.0], [0.0, 1.0]]; Set Apply 1/sqrt(d_k) scaling to True.

Observe: Calculated results for this setup, compared with the starting inputs: Raw attention scores = [3.0, 0.0] (starting value: [1.0, 0.0]); Scaled attention scores = [2.1213203, 0.0] (starting value: [0.70710678, 0.0]); Attention weights = [0.8929582, 0.1070418] (starting value: [0.66976155, 0.33023845]); Attention output = [0.8929582, 0.1070418] (starting value: [0.66976155, 0.33023845]).

Why: Dividing by sqrt(d_k) reduces the magnitude of the score differences, which makes the softmax less peaked. Without scaling, larger score differences push softmax toward a one-hot distribution, which is the behavior the scaling factor is designed to counteract.

Where this demonstration stops

The lesson uses d_k = 2 and two keys; real models use larger dimensions and many keys, which changes the numerical scale of scores and weights.

Scaling by 1/sqrt(d_k) is not an arbitrary normalization; it counteracts the growth of dot-product variance with dimension, keeping softmax gradients from becoming extremely small.

One query vector q, two key vectors and two value vectors (d_k = d_v = 2). The lesson computes scores, scaled scores, attention weights, and the output vector. It does not cover multi-head attention, masking, training, or learned projections.

  • The lesson uses d_k = 2 and two keys; real models use larger dimensions and many keys, which changes the numerical scale of scores and weights.
  • Masking, dropout, and multi-head concatenation are outside this scope.
  • The query, keys, and values are already projected vectors; this lesson does not compute the learned linear projections.
  • Only one query is used, so the attention weight vector has one entry per key and the output is a single value vector.
